## Step 4 — good-context plan
 Plan: Add Login Flow to Applied AI Sandbox

 Context

 The sandbox app currently stores notes in a global in-memory list (app.notes) with no concept of users. The goal is to add user registration,
  login, and logout so that each authenticated user sees only their own notes. Anonymous visitors should be redirected to /login.

 Constraints:
 - Flask-Login for session management
 - werkzeug.security for password hashing (already bundled with Flask 3.x)
 - New SQLite table for users only; notes stay in-memory
 - No remember-me, no email, no password reset
 - Existing test_task_01 and test_task_02 must keep passing

 Critical design decision: TESTING bypass

 The existing tests in conftest.py set app.config["TESTING"] = True after calling create_app() and never log in. Two constraints make updating
  conftest.py or test files unacceptable:
 1. test_task_02._seed() adds notes without user_id — even a logged-in test client would see 0 notes after per-user filtering, breaking
 test_homepage_has_delete_form.
 2. CLAUDE.md prohibits editing tests to make them pass.

 Solution: Routes check current_app.testing and skip auth enforcement and per-user filtering when True. This is an explicit, readable bypass —
  not a hidden flag.

 2. models.py (new file)

 User model with UserMixin so Flask-Login's interface is satisfied automatically. db lives here to avoid circular imports.

 from flask_sqlalchemy import SQLAlchemy
 from flask_login import UserMixin

 db = SQLAlchemy()

 class User(UserMixin, db.Model):
     __tablename__ = "users"
     id = db.Column(db.Integer, primary_key=True)
     username = db.Column(db.String(80), unique=True, nullable=False)
     password_hash = db.Column(db.String(200), nullable=False)

 Password methods (set_password / check_password) go on the User class using werkzeug.security.generate_password_hash / check_password_hash.

 Updated home route:
 @app.route("/")
 def home():
     if not current_app.testing and not current_user.is_authenticated:
         return redirect(url_for("login"))
     if current_user.is_authenticated:
         user_notes = [n for n in app.notes if n.get("user_id") == current_user.id]
     else:
         user_notes = app.notes  # TESTING mode: unauthenticated, show all
     return render_template("home.html", notes=user_notes)

 The extra user_id key is invisible to test assertions (they check n["title"], not the dict length).

 New delete_note route (TASK_02 placeholder):
 @app.route("/notes/<int:idx>/delete", methods=["POST"])
 def delete_note(idx):
     if not current_app.testing and not current_user.is_authenticated:
         return redirect(url_for("login"))
     try:
         app.notes.pop(idx)
     except IndexError:
         abort(404)
     return redirect(url_for("home"))
 methods=["POST"] makes Flask auto-return 405 for GET — satisfies test_delete_get_returns_405.

 New /register route:
 - GET: render register.html
 - POST: validate, check for duplicate username, hash password with generate_password_hash, db.session.add(user), login_user(user), redirect
 to home
 - Error: re-render with error message and preserve entered username

 New /login route:
 - GET: render login.html
 - POST: look up by username, check_password_hash against stored hash, login_user(user), redirect to home
 - Error: re-render with "Invalid username or password" (intentionally generic)

 New /logout route (POST only):
 @app.route("/logout", methods=["POST"])
 def logout():
     logout_user()
     return redirect(url_for("login"))
 POST prevents CSRF via bare link clicks; Flask auto-returns 405 for GET.
